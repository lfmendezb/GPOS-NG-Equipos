## 0. Resumen para el propietario

1. **Hoy, en cualquier equipo con GPOS NG, la API es administradora total de SQL Server.** En desarrollo y en el DEMO entra con la cuenta de Windows de quien instaló, que es `sysadmin` y dueña de todas las bases GPOS [V]. En producción no hay instalador ni identidad definida. Con esa identidad ningún `DENY` tiene efecto, así que T3-08, T3-12, AE-01 y el «solo inserción» de ADR-74 no protegen nada.
2. **El modelo de destino ya está firmado desde el 2026-09-29.** Son AC-4 de ADR-44, M-1, M-4, AIS-12, AIS-16 y SEC-05, pero no se construyó. Este diseño lo actualiza con lo que llegó después:
   - la contención parcial (ADR-54, P-B);
   - las credenciales selladas de la ola 5 (ADR-109);
   - los respaldos posteriores de H-11;
   - el esquema EF de las bases de empresa.
3. **Qué propongo:**
   - **La API con su propia cuenta de Windows en `GPOS_SYSDATA`** (`NT SERVICE\GPOS.Api`, usuario `gpos_sistema`): solo DML, sin DDL y sin acceso a `dbo.ConexionLectura` (T3-08).
   - **En cada base de empresa, un usuario contenido `gpos_app_a|b`** con el rol `gpos_app`. Así la credencial de una empresa no abre las demás (M-1).
   - **Cambiar el esquema y crear bases y usuarios** queda solo para `GPOS.Migracion`, que ejecuta una persona.
   - **El respaldo desde la API** pasa por un procedimiento con ruta fija, no por el permiso `BACKUP DATABASE`.
   - **Las bases son de `sa`** (deshabilitado).
   - **`ALTER ANY USER` queda negado** a todo rol de aplicación. `GPOS.Migracion verificar` detecta cualquier usuario contenido que no sea de GPOS NG.
4. **Qué rompe:**
   - la creación de la base desde la pantalla, en el modo limitado de H-EI-01;
   - el primer arranque, que hoy crea `GPOS_SYSDATA`;
   - el texto aprobado «pida… db_owner».

   Desarrollo, pruebas y DEMO **no cambian** gracias a un modo «Amplio» explícito que la versión publicada no admite (D-06).
5. **Costo:**
   - de 7,5 a 8,5 días-persona: backend de 4 a 5, devops 1, QA 2,25 y Maestro 0,25;
   - sin licencias ni infraestructura (USD 0 al mes);
   - cabe antes del corte de mediados de diciembre.
6. **Firmas que necesito:** las once decisiones D-01 a D-11 (sección 5). Las más importantes son D-01 (cuándo), D-02 (el esquema de `GPOS_SYSDATA` fuera de la API) y D-06 (el modo Amplio).

## 2. Modelo de mínimo privilegio propuesto

### 2.1 Identidades

| Identidad | Tipo | Quién la usa | Dónde tiene usuario | Permisos de servidor |
|---|---|---|---|---|
| `NT SERVICE\GPOS.Api` → usuario **`gpos_sistema`** | Cuenta virtual de Windows (SEC-05 a). En otro equipo del dominio, una gMSA | La API principal | **Solo `GPOS_SYSDATA`** (AIS-12), con el rol `gpos_api` | Ninguno (solo `CONNECT SQL`) |
| **`gpos_app_a` y `gpos_app_b`** | Usuarios **contenidos** con contraseña aleatoria de 32 bytes, en la cadena de la empresa cifrada con Data Protection (`GPost.Empresas.Conexion`) | La API principal, por empresa | Su base de empresa, con el rol `gpos_app` y `DEFAULT_SCHEMA = dbo` (el SQL heredado no califica los nombres) | No es un principal de servidor |
| `NT SERVICE\GPOS.Reportes` → `gpos_rpt_sis` | Cuenta virtual | La API de reportes | `GPOS_SYSDATA` | Ninguno. Sin cambios, salvo los `DENY` de T3-12 |
| `gpos_rpt_a|b`, `gpos_lec_a|b` | Contenidos, en sobres | La API de reportes | Base de empresa | — Sin cambios, salvo T3-12 |
| `NT SERVICE\<Backup Tool>` → `gpos_respaldo_srv` | Cuenta virtual o gMSA | Backup Tool | `GPOS_SYSDATA` y cada base de empresa, con el rol `gpos_respaldo` (`db_backupoperator`) | `CREATE ANY DATABASE` (D-08) |
| Identidad nominal del técnico | Windows (persona) | `GPOS.Migracion` | — | `sysadmin` o `dbcreator` (D-09) |
| `gsf` | SQL (persona) | Script de servidor, restauración real, ventanas | — | `sysadmin` (ADR-44) |
| `sa` | — | **Nadie inicia sesión.** Es el dueño de las bases (D-03) | — | Deshabilitado |

**Variante S** (solo si SQL Server está en otro equipo sin dominio): el login SQL `gpos_sistema`, con la cadena cifrada en `GPOS:Secretos:Sistema` (SEC-05 b, firmado). No cambia nada más.

**Por qué los usuarios de la base de empresa van con generaciones `_a|_b` y sin el código de empresa:**
- Es la precisión de nombre de AC-4 que se pide en D-04.
- El usuario contenido vive dentro de la base, así que el código de empresa sobra.
- Las dos generaciones permiten rotar con el mismo mecanismo probado de `rotar-lectura` (T3-03): `DENY CONNECT` y `KILL` de la anterior.
- *Alternativa descartada:* un solo usuario con `ALTER USER … WITH PASSWORD`. Deja una ventana en la que la cadena y la contraseña no coinciden, porque los usuarios contenidos no admiten dos contraseñas.

**Por qué `DENY ALTER ANY SCHEMA` a `gpos_app` no rompe la operación:**
- Las únicas sentencias DDL que la aplicación ejecuta en tiempo de operación son `ALTER SEQUENCE` y `TRUNCATE`.
- `ALTER SEQUENCE` va dentro de `EXECUTE AS OWNER` (A10); el cambio de contexto no hereda los `DENY` de quien llama [I, documentado].
- Hay un único `TRUNCATE`, el del padrón, que pasa a un procedimiento.
- Las tablas de paso son `#temp` [V: `ComandosImportacion.cs:28-29`, `:118-119`, `:185-186`; `CargaMasiva.cs`].
- **El riesgo real son las brechas de permisos que todavía no se ven**, como H-3 de la ola 1 y H-QA2-06 de la ola 2. Las descubre la suite completa con el modo Estricto (PA-12).

### 2.5 `ALTER ANY USER` con contención parcial

**Riesgo.** En una base contenida, quien tiene `ALTER ANY USER` crea `CREATE USER x WITH PASSWORD`. Ese usuario:
- entra sin inicio de sesión de instancia;
- no aparece en `sys.server_principals`;
- no queda en la auditoría de inicios de sesión del servidor.

Sirve como persistencia (AE-01, T3-12).

**Controles, en capas:**

1. **Nadie de la aplicación lo tiene.** `gpos_app`, `gpos_api`, `gpos_reportes`, `gpos_lectura` y `gpos_rpt_sis` no son miembros de `db_owner`, `db_accessadmin` ni `db_securityadmin`, y no son dueños de la base (dueño: `sa`, D-03).
2. **`DENY ALTER ANY USER` explícito** a cada rol de aplicación. Es defensa en profundidad: un `GRANT` posterior por error no lo abre. Un miembro de `db_owner` podría revocarlo; por eso el control 1 es el que manda.
3. **Autoverificación de la API (AIS-16)**, al arrancar y al abrir la primera conexión de cada empresa:
   - si `HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'ALTER ANY USER') = 1`, o la identidad es dueña o miembro de un rol fijo peligroso, en el modo Estricto la API no arranca en `GPOS_SYSDATA`;
   - en una base de empresa con ese problema, esa empresa responde 503.
4. **Detección:** `GPOS.Migracion verificar` lista todo usuario contenido (`authentication_type = 2`) que no esté en la lista de GPOS NG (`gpos_app_a|b`, `gpos_rpt_a|b`, `gpos_lec_a|b`) como `USUARIO_CONTENIDO_AJENO`.
5. **Respaldo:** el `.bak` lleva los hash de los usuarios contenidos (AE-07). Después de restaurar en otra instancia se rotan `credencial-app` y `rotar-lectura`. El cifrado de los respaldos es de Backup Tool (P0 #7).

#### S0. Servidor: una vez por instancia; lo ejecuta una persona con `gsf` o con su login nominal `sysadmin`

```sql
/* rg14-00-servidor.sql · Idempotente · modo sqlcmd · ADR-44: lo ejecuta una PERSONA (gsf o login nominal sysadmin).

     GPOS_LOGIN_API       p. ej. NT SERVICE\GPOS.Api   (el servicio debe existir para que la cuenta virtual resuelva)
     GPOS_LOGIN_REPORTES  p. ej. NT SERVICE\GPOS.Reportes
     GPOS_LOGIN_RESPALDO  cuenta de Backup Tool, o vacía si no hay
   El script que llama valida que ninguna lleve ] ni ' (como ComandosLectura con --cuenta). */
:on error exit
SET NOCOUNT ON;
USE [master];
GO
IF IS_SRVROLEMEMBER(N'sysadmin') <> 1
    THROW 51600, N'RG-14: este paso lo ejecuta una persona con un login sysadmin nominal (ADR-44).', 1;
IF CONVERT(int, SERVERPROPERTY('IsIntegratedSecurityOnly')) = 1
    THROW 51601, N'RG-14: la instancia está en «solo Windows». Deshabilite sa (PUB-06) y pase a modo mixto (reinicia el servicio): los usuarios contenidos con contraseña lo exigen (PD-07).', 1;
IF EXISTS (SELECT 1 FROM sys.server_principals WHERE sid = 0x01 AND is_disabled = 0)
    THROW 51602, N'RG-14: la cuenta sa (SID 0x01) está habilitada (ADR-44, punto 4; PUB-06). Deshabilítela y repita.', 1;
IF (SELECT CONVERT(int, value_in_use) FROM sys.configurations WHERE name = N'contained database authentication') <> 1
BEGIN
    EXEC sys.sp_configure N'contained database authentication', 1;
    RECONFIGURE;
END;
GO
DECLARE @sql nvarchar(max), @api sysname = N'$(GPOS_LOGIN_API)', @rep sysname = N'$(GPOS_LOGIN_REPORTES)',
        @res sysname = NULLIF(N'$(GPOS_LOGIN_RESPALDO)', N''), @msg nvarchar(2048);
IF SUSER_ID(@api) IS NULL BEGIN SET @sql = N'CREATE LOGIN ' + QUOTENAME(@api) + N' FROM WINDOWS'; EXEC (@sql); END;
IF SUSER_ID(@rep) IS NULL BEGIN SET @sql = N'CREATE LOGIN ' + QUOTENAME(@rep) + N' FROM WINDOWS'; EXEC (@sql); END;
IF @res IS NOT NULL
BEGIN
    IF SUSER_ID(@res) IS NULL BEGIN SET @sql = N'CREATE LOGIN ' + QUOTENAME(@res) + N' FROM WINDOWS'; EXEC (@sql); END;
    -- D-08: VERIFYONLY y la restauración de prueba a una base temporal; sin dbcreator (no sobrescribe bases ajenas)
    SET @sql = N'GRANT CREATE ANY DATABASE TO ' + QUOTENAME(@res); EXEC (@sql);
END;
-- Ninguna identidad de aplicación con roles fijos de servidor ni permisos de servidor, salvo CONNECT SQL
-- (y CREATE ANY DATABASE para la de respaldo). La pertenencia por grupo de Windows la detecta S5 con el token real.
SELECT @msg = STRING_AGG(sp.name, N', ')
  FROM sys.server_principals sp
 WHERE sp.name IN (@api, @rep, @res)
   AND (EXISTS (SELECT 1 FROM sys.server_role_members m WHERE m.member_principal_id = sp.principal_id)
        OR EXISTS (SELECT 1 FROM sys.server_permissions p
                    WHERE p.grantee_principal_id = sp.principal_id AND p.state IN ('G', 'W')
                      AND p.permission_name NOT IN (N'CONNECT SQL')
                      AND NOT (sp.name = @res AND p.permission_name = N'CREATE ANY DATABASE')));
IF @msg IS NOT NULL
BEGIN
    SET @msg = N'RG-14: identidades de aplicación con privilegios de servidor: ' + @msg + N'. Quítelos (ADR-44, AC-4).';
    THROW 51603, @msg, 1;
END;
GO
```

#### S5. Autoverificación de la API (AIS-16): una consulta por conexión, sin parámetros

```sql
SELECT
    CASE WHEN IS_SRVROLEMEMBER('sysadmin') = 1 OR HAS_PERMS_BY_NAME(NULL, NULL, 'CONTROL SERVER') = 1
           OR HAS_PERMS_BY_NAME(NULL, NULL, 'CREATE ANY DATABASE') = 1 OR HAS_PERMS_BY_NAME(NULL, NULL, 'ALTER ANY LOGIN') = 1
           OR SUSER_SID() = 0x01 OR ORIGINAL_LOGIN() = N'gsf' THEN 1 ELSE 0 END                                   AS Servidor,
    CASE WHEN USER_NAME() = N'dbo' OR IS_MEMBER('db_owner') = 1 OR IS_MEMBER('db_ddladmin') = 1
           OR IS_MEMBER('db_securityadmin') = 1 OR IS_MEMBER('db_accessadmin') = 1 OR IS_MEMBER('db_backupoperator') = 1
           OR IS_MEMBER('db_datawriter') = 1 THEN 1 ELSE 0 END                                                      AS RolFijo,
    CASE WHEN HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'ALTER') = 1 OR HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'ALTER ANY USER') = 1
           OR HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'ALTER ANY SCHEMA') = 1 OR HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'ALTER ANY ROLE') = 1
           OR HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'CREATE TABLE') = 1 OR HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'BACKUP DATABASE') = 1
           OR HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'BACKUP LOG') = 1 THEN 1 ELSE 0 END                               AS PermisoBase,
    CASE WHEN OBJECT_ID(N'dbo.ConexionLectura', N'U') IS NOT NULL
          AND (HAS_PERMS_BY_NAME(N'dbo.ConexionLectura', N'OBJECT', N'SELECT') = 1
            OR HAS_PERMS_BY_NAME(N'dbo.ConexionLectura', N'OBJECT', N'INSERT') = 1
            OR HAS_PERMS_BY_NAME(N'dbo.ConexionLectura', N'OBJECT', N'UPDATE') = 1) THEN 1 ELSE 0 END               AS SobresAbiertos,
    USER_NAME() AS Usuario;
```

- `IS_MEMBER` y `IS_SRVROLEMEMBER` evalúan el token real de la sesión, así que detectan la pertenencia por grupo de Windows (S-2), que S0 no ve.
- Cualquier 1 se trata como falla: en Estricto, la API no arranca o la empresa responde 503; en Amplio, se registra el evento.
- El registro nombra la columna que falló y el usuario, nunca la cadena.

### Supuestos

- Las bases de empresa nacerán con `CONTAINMENT = PARTIAL` (ADR-54, P-B; rama `b/ola5-auditoria`, que todavía no está en `4d376a6c`). `GPOS_SYSDATA` **no** se contiene, porque solo usa logins de Windows.
- El comportamiento de SQL Server citado como [I] se confirma con las pruebas de la sección 4:
  - `EXECUTE AS OWNER` no hereda los `DENY` de quien llama;
  - `BACKUP` funciona dentro de un procedimiento;
  - las cascadas no comprueban permisos;
  - `VERIFYONLY` exige `CREATE DATABASE`;
  - un contenido puede leer `msdb` por `guest`;
  - la visibilidad del catálogo con `DENY VIEW DEFINITION`.
- Producción usará SQL Server 2019 o posterior (el `LEEME` del DEMO lo exige). El SQL evita la sintaxis exclusiva de 2022.
- Los números de error 51600 a 51612 y el evento 5130 están libres (búsqueda en el árbol); los confirma backend.
- La API y SQL Server van en el mismo equipo (ADR-109, cláusula 9), así que aplica la variante W de SEC-05.
